# Notifications — Acceptance Criteria

> **Status:** Draft (dependent on TBD catalog)
> **Last updated:** 2026-08-06

- [ ] Contract expiry notifications are generated per decided thresholds and delivered to decided recipients.
- [ ] Low-stock alerts are generated when balances fall below item minimum levels.
- [ ] Users receive and can list only their own notifications, always within their tenant.
- [ ] No notification is ever delivered across tenants.
- [ ] Notification generation runs via queued jobs carrying tenant context.
- [ ] Read/unread behavior per decided model.
- [ ] No notification types exist beyond those required by MVP modules.
